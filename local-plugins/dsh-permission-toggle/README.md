# dsh-permission-toggle

三件事：

1. **输入框里的权限芯片换成不弹确认的版本** —— 菜单里直接选「完全权限」就切过去，不再弹
   「我已了解风险」的确认框。
2. **Tab 循环权限模式** —— 光标在输入框里按 Tab，按目录顺序轮换所有可用预设
   （默认：仅可查看 → 工作区内修改 → 完全权限 → 自动审查 → 仅可查看…），
   并在输入框上方提示当前模式。
3. **审批卡片上多两个按钮** —— 工具请求提权时，除了「拒绝 / 允许一次」，
   旁边还有「切换为完全权限并同意」和「切换为自动审批」。

## 为什么不弹确认

核心的权限芯片在选 Full access（以及实验性的 Auto review）时会先弹 `RiskConfirmation`：
一个「我已了解风险」的勾选框 + 一个启用按钮。这道闸门**只存在于组件里**；真正的写入路径
`/permission <预设>` 本身没有闸门 —— 它往会话里写两条旋钮事件（`sandbox/mode`、
`approval/policy`），`permissions` 投影再把新值推回芯片。

所以本插件做的是**用同一个 cell 的影子注册替换那个组件**：

- `conversation.input.permission` 是 `single` 槽位，同一 cell 里 `priority` 最低者渲染；
- 插件以 `priority: -1` 注册自己的 `PermissionChip`，触发按钮、菜单、图标、文案、紧凑
  布局的 `@container` 规则都照抄核心，只是选择动作直接走 `/permission`；
- 卸载插件，核心芯片和确认框一起回来。

## Tab 循环

按**目录顺序**走当前所有可用预设（`options`），所以默认是：
仅可查看 → 工作区内修改 → 完全权限 → 自动审查 → 回到仅可查看。
实验性的「自动审查」是运行时贡献的预设，也在轮换里（切进去等同于点菜单里那一项）。
每次切换在输入框上方弹 1.6 秒提示；切换进行中再按会被忽略。

## 审批卡片上的两个按钮

工具带 `sandbox_permissions` 提权时，宿主会走审批瀑布；卡片本身是核心的工厂槽位
`conversation.approval.card`（每个工厂只能有一个定义，替不掉），所以插件改走上一层：

- 以 `priority: 0.5` 在 `conversation.composer` 链上注册一个只匹配「待审批」的选择器
  （核心审批面板是 `priority: 1`，问句卡片和子代理面板不受影响）；
- 组件里用 `renderFactorySlot('conversation.approval.card', …)` **原样渲染核心卡片**，
  所以工具详情、Enter/Esc 快捷键、已答状态都还是核心的；
- 两个按钮用 `createPortal` 塞进卡片自己的 `actionRow`，和「拒绝 / 允许一次」同一行；
- 该行原本不换行，四个按钮在手机上会挤成竖排字形并冲出卡片边缘，所以插件找到这一行时给它
  打上 `data-dsh-pt-row`，由插件样式表允许换行（桌面一行放得下就还是一行）。

两个按钮都是「**先切模式、再把当前这一次放行**」：

- 切换为完全权限并同意 → `/permission danger-full-access` → 允许一次；
- 切换为自动审批 → `/permission auto` → 允许一次。

先切模式再放行是刻意的：切换失败（比如宿主没开自动审查）就保持卡片不动并提示失败，
不会出现「模式没切过去但这一次已经放行」。

> 只想切模式、不想放行当前这一次的话，改 `act()` 里那句 `approval.answer('allowed-once')` 即可。

### 为什么这行是只读的

快捷键面板（设置 → 通用 → 快捷键，或 `/shortcuts`）里会有
**应用操作 → 切换权限模式 → Tab**，但没有「修改」按钮。原因在核心：

- `bindingIssue()` 对裸 Tab 报 `modifier-required`，对任何带修饰键的 Tab 报 `reserved`；
- Web 运行时还会再过一道 `isWebBindingAllowed()`，裸 Tab 同样不合法。

Tab 进不了可编辑快捷键表。插件改用**固定动作**（fixed command）注册：出现在同一张表里、
显示为 Tab、锁住该组合不让别的命令占用。想换键只能改 `client.js` 里的 `bindings`。

## 生效范围

Tab 只在**光标位于输入框**（`[data-composer-card]` 内）且没有弹窗/菜单打开时生效：

- 页面、侧栏、终端、各种表单里的 Tab 仍是原生的焦点移动；
- Shift+Tab 不受影响，仍可把焦点反向移出输入框；
- 输入法组合中的 Tab、按住不放的重复 Tab 都不动作。

浏览器里 Tab 是第一焦点导航键，全局吞掉会让整个界面无法用键盘操作，所以没有全局接管。

## 还没覆盖的两处

同一个 `RiskConfirmation` 还挂在另外两个**核心组件**上，本插件没有替换它们：

- 设置 → 通用 → 「权限」行（设置**以后新建会话**的默认模式）
- `/permission` 斜杠命令的弹层

需要的话可以继续用影子注册接管（设置行要自己接 `configForms` 镜像），但那是另一份要跟着核心
维护的 UI。

## 停用

在插件管理里关掉 `dsh-permission-toggle`：芯片回到核心版本（确认框回来），快捷键面板那行消失，
Tab 恢复原生行为。
