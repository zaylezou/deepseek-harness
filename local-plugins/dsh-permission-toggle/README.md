# dsh-permission-toggle

在对话输入框里按 **Tab**，在「完全访问」和之前的权限预设之间切换。
切换走宿主的 `/permission <预设>` 写入路径，所以**启用完全访问不再弹风险确认框**。

## 为什么要插件

核心的权限芯片（以及 设置 → 通用 → 权限）在选「Full access」时会先弹
`RiskConfirmation`：一个「我已了解风险」的勾选框 + 一个「启用完全访问」按钮。
这道闸门是核心 UI 的一部分，只挡在选择动作前面；真正的写入路径
`/permission <预设>` 本身没有闸门 —— 它往会话里写两条旋钮事件
（`sandbox/mode`、`approval/policy`），`permissions` 投影把新值推回芯片。

本插件直接调这条路径：一次按键完成切换，没有勾选框。

## 键位

快捷键面板（设置 → 通用 → 快捷键，或 `/shortcuts`）里多一行
**应用操作 → 切换权限模式 → Tab**。

这一行是**只读**的，不能在面板里改键。原因在核心：

- `bindingIssue()` 对裸 Tab 报 `modifier-required`，对任何带修饰键的 Tab 报 `reserved`；
- Web 运行时还会再过一道 `isWebBindingAllowed()`，裸 Tab 同样不合法。

所以 Tab 根本进不了可编辑快捷键表。插件改用**固定动作**（fixed command）注册：
它会出现在同一张表里、显示为 Tab、并把该组合锁住不让别的命令占用，只是没有「修改」按钮。
想换键就得改 `client.js` 里的 `bindings`。

## 生效范围

Tab 只在**光标在输入框里**（`[data-composer-card]` 内）且没有弹窗/菜单打开时生效：

- 页面、侧栏、终端、各种表单里的 Tab 仍是原生的焦点移动；
- Shift+Tab 不受影响，仍然可以把焦点反向移出输入框；
- 输入法组合中的 Tab、按住不放的重复 Tab 都不动作。

之所以不全局接管：浏览器里 Tab 是第一焦点导航键，全局吞掉会让整个界面无法用键盘操作。

## 行为

- 当前不是完全访问 → 切到「完全访问」（预设打包 = `danger-full-access` 沙箱 + `never` 审批策略，
  所以同一次切换既解除沙箱也停掉逐次审批弹窗）。
- 当前是完全访问 → 回到进入完全访问之前的那个预设；没记到就用 `workspace-write`。
  记忆按会话存在当前页面里（刷新页面即清空），`custom` / `auto` 这种派生状态不记。
- 每次切换都会在输入框上方弹一条 1.6 秒的状态提示（成功或失败原因）。
- 切换进行中再按 Tab 会被忽略，不会排队打第二条命令。

## 停用

在插件管理里关掉 `dsh-permission-toggle`：快捷键面板里那行消失，Tab 回到原生行为，
权限芯片的确认框照旧。
