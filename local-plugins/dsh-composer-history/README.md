# dsh-composer-history

给输入框加**终端式历史**：把已经发过的消息填回输入框，像终端里按 ↑ 翻上一条命令。

- **电脑**：光标在输入框里直接按 **↑ / ↓**，不占用界面空间。
- **手机 / 平板**：没有方向键，所以输入框工具行左端多一对 **↑ ↓** 按钮。
- 两者共用同一份历史、同一套规则：一开始翻时输入框里的内容（如果有）会被存下来，
  翻到最新一条后再按一次 ↓ 就恢复它；发送或手动清空后回溯位置自动复位，
  下一次 ↑ 从最新一条开始（包括刚发的那条）。

## 键盘什么时候接管

输入框是多行的，↑↓ 平时要挪光标，所以只在**边界**上接管，其余情况完全保持原样：

| 当前草稿 | ↑ | ↓ |
| --- | --- | --- |
| 空 | 取最新一条 | 不动（没在回溯中） |
| 就是插件刚填进去的那条，光标在首/尾 | 更早一条 | 较新一条；到最新时恢复原草稿 |
| 自己打的字，光标在**最开头** | 更早一条（草稿被存起来） | 不接管 |
| 自己打的字，**单行**且光标在末尾 | 更早一条（草稿被存起来） | 不接管 |
| 多行草稿，光标在中间/末尾 | 不接管（正常挪光标） | 不接管 |
| 正在用 `/` 命令或 `@` 引用的选择菜单 | 不接管（菜单要用方向键） | 同左 |

这些边界都是「ArrowUp 本来什么也不做」的位置（空输入、文档最前、单行末尾），
所以在这些地方接管不会吃掉正常的挪光标；多行草稿里照常上下挪。

带 Shift / Ctrl / Cmd / Alt 的组合键、输入法组字中，一律不接管。

## 设备判断

按钮只在**手持设备**上出现，判断顺序：

1. `UA` 里有 `Android / iPhone / iPad / iPod / Mobile / HarmonyOS / Windows Phone / Kindle`
   —— 手机、安卓平板、iPad 都命中（iPadOS 桌面版 UA 仍带 `Mobile`）；
2. 否则看「有触点 + 主指针是 coarse」：兜住 iPad 桌面模式（UA 伪装成 Mac，但 Mac 没有触点）；
   带鼠标的触屏笔记本主指针仍是 fine，不显示按钮。

想临时改判断（调试用，不写进配置）：

```js
localStorage.setItem('dsh.composer-history.force-buttons', '1')  // 强制显示
localStorage.setItem('dsh.composer-history.force-buttons', '0')  // 强制隐藏
localStorage.removeItem('dsh.composer-history.force-buttons')    // 回到自动
```

## 数据来源

历史不是插件自己记的，而是从**当前会话的聊天记录**里推出来的——会话日志是唯一可信来源，
插件内存只是派生缓存：

- `user` 节点 = 已经进入会话的用户消息；
- `steering` 节点 = 智能体运行中插进去的消息（同样是你发过的话，也一并回溯）；
- 只取文本块：附件、图片、`@` 引用芯片都是浏览器自己持有的对象，无法从聊天记录里重建，
  所以只有附件没有文字的消息会被跳过，而不是填一个空输入框；
- 连续重复的消息会合并（连发三次「继续」只占一条），避免按 ↑ 按到手酸。

## 状态

| 情形 | 按钮 / 快捷键 |
| --- | --- |
| 会话里还没有可回溯的消息 | ↑ 禁用 |
| 已经翻到最早一条 | ↑ 禁用 |
| 还没开始回溯 | ↓ 禁用 |
| 正在发送 / 命令执行 / 无发送权限 | 都禁用（键盘也不接管） |

## 限制

- 只能回溯**当前已加载的聊天窗口**（会话记录是分页加载的，往前翻到窗口边界为止）；
- 只恢复文字，不恢复图片和附件。

## 实现要点

- 槽位：`conversation.input.left`（`conversation.composer.bar` 声明的工具行左端，
  owner 自己不渲染时整格为空，所以是加法而不是替换）。桌面端整格返回 `null`，不占位。
- 读取聊天记录：`useChat(snapshot => snapshot.nodes)` 拿到的是**稳定的实时读取器**，
  `snapshot.order` 只在节点增删时换引用，所以历史列表只结构性变化时重算，不随流式 token 重算。
- 写入草稿：走 composer 自己的公开动作 `inputActions.setDraft(text)`（整段替换，一个撤销步），
  不碰编辑器 DOM，也不直接派发键盘事件。
- 光标边界：`inputActions.captureInsertion()` 给出编辑器自己的选区坐标，不读 DOM selection。
- 键盘监听：document 捕获阶段一次安装；处理函数与最新状态放在 ref 里刷新，避免闭包读到旧值，
  连续快按 ↑ 也不会因为 React 还没重渲染而丢步。
- 焦点：按钮 `mousedown` 时 `preventDefault`，和输入框里其他工具按钮一致，按完光标还在输入框。
- `pending` ref 记住「刚写进去的文字」：编辑器提交到 store 之间有一个渲染空档，
  只有确认写进去之后，输入框变空才被当成「发送/清空」并复位回溯位置。

## 安装

```bash
/opt/dsh/deepseek-harness/local-plugins/dsh-safe-install/dsh-safe-install.sh \
  /opt/dsh/deepseek-harness/local-plugins/dsh-composer-history
```

装完刷新页面即可；客户端改动不需要重启服务（服务端这一半是 no-op）。
